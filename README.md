# KODAIRA祭 WEBパンフレット（試作版）

「WEBパンフ改造案 vol.1」と「WEBパンフイメージ」をもとに作った、動く試作品です。
ビルド作業は不要で、`index.html` をブラウザで開けばそのまま動きます。

---

## 1. まず動かす

**いちばん簡単な方法**：`index.html` をダブルクリック。
（データを普通のJSファイルとして読んでいるので、`file://` のままでも動きます）

**スマホで確認したい / 人に配りたいとき**：後述の「4. 公開する」を参照。

初期状態は **デモモード**（`js/config.js` の `demoMode: 'auto'`）です。
待ち人数・売上・レビューはそれらしい数字が自動生成され、数分ごとにゆっくり変化します。
会議で見せる分にはこのままで十分です。

---

## 2. 5つの機能

企画書の5案がそのまま5画面になっています。

| 画面 | 企画書での案 | 実装したこと |
| --- | --- | --- |
| ホーム | ホーム画面イメージ①② | 「この後15:00〜」の直近企画を大きく表示。5機能へのタイル。いま空いている／並んでいる店 |
| リアルタイム混雑 | ⑤リアルタイム混雑表示 | 待ち人数と「およそ○分待ち」を一覧表示。カテゴリ絞り込み、混んでいる順／空いている順 |
| 模擬店・企画情報 | 模擬店ページ | 検索・カテゴリ絞り込み・詳細ページ（場所／時間／価格／説明／タグ） |
| 来場者レビュー | ④来場者参加型レビュー | 星タップだけで投稿。平均が即座に動く。模擬店は売上個数と学内順位も表示 |
| おすすめ模擬店診断 | ③おすすめ模擬店診断 | 二択のアキネイター方式。最初の質問だけ「模擬店／企画」で固定、以降は候補を一番きれいに二分する質問を自動で選ぶ |
| マイスケジュール | ①カスタマイズスケジュール | コダコマ風の時間割。重なる予定は横に並ぶ。終日企画と「行きたい模擬店」は別枠 |
| キャンパスナビ | ②ナビ機能 | 3Dは断念、**階層別2Dマップ**。入口から目的地までの経路を矢印で表示 |

### 診断の質問を足したいとき

`js/quiz.js` の `QUIZ_QUESTIONS` に足すだけです。分岐表を書く必要はありません。
質問の出す順番はコードが勝手に決めます（候補が半々に割れる質問を優先）。

## 3. Googleスプレッドシートにつなぐ

### 3-1. トラメガ隊の入力フォームを作る

Googleフォームを1つ作り、次の3つの質問を用意します。

| 質問 | 形式 | 備考 |
| --- | --- | --- |
| 模擬店ID | 記述式 or プルダウン | `data/shops.js` の `id`（例 `s20`）。プルダウン推奨 |
| 待ち人数 | 記述式（数値） | 並んでいる人数 |
| 売上個数 | 記述式（数値） | 任意。1年生から聞ければ |

回答スプレッドシートが自動でできます。

> **列名は多少ずれても大丈夫です。**
> 「待ち人数／並び人数」「模擬店ID／企画ID／ID」など、よくある言い換えは吸収します。

### 3-2. スプレッドシートをCSVとして公開する

スプレッドシートで **ファイル → 共有 → ウェブに公開** → 形式に **カンマ区切り形式(.csv)** を選んで公開。
出てくるURL（`.../pub?gid=0&single=true&output=csv`）をコピーします。

### 3-3. 設定に貼る

`js/config.js` を開いて貼るだけです。

```js
congestionCsvUrl: 'https://docs.google.com/spreadsheets/d/e/2PACX-xxxx/pub?gid=0&single=true&output=csv',
```

これで `demoMode: 'auto'` のまま実データに切り替わります。
同じ店の行が複数あるときは **いちばん下の行（＝最新の報告）** を使います。
60秒ごとに自動で取り直します（`refreshIntervalSec` で変更可）。

### 3-4. レビューも集計したいとき

同じ手順でレビュー用フォーム（質問は「模擬店ID」「評価」）を作り、
`reviewCsvUrl` に公開CSVのURLを入れます。アプリ側で平均を計算します。

さらに **アプリから直接★を送りたい** 場合は、フォームの「事前入力したURLを取得」で
`entry.数字` を調べて `reviewFormPostUrl` と `reviewFormFields` に入れてください。
未設定のときは端末内（localStorage）にだけ保存され、平均表示には反映されます。

## 4. スマホで開く（自分で確認するとき）

`file://` はスマホに持っていけないので、PCで小さなサーバーを立てて同じWi-Fi経由で見ます。

```
cd "C:\Users\meizh\OneDrive\デスクトップ\KODA祭　広報\webパンフ"
node serve.js
```

起動すると `http://192.168.x.x:4321/` のようなURLが表示されるので、
**PCと同じWi-Fiにつないだスマホ**のブラウザでそれを開きます。止めるときは `Ctrl + C`。

- 初回だけWindowsファイアウォールの確認が出ることがあります。**プライベートネットワーク**を許可してください
- 大学のWi-Fiなど、端末同士の通信が遮断されているネットワークでは繋がりません。スマホのテザリングにPCをつなぐと通ります
- ポートが使用中なら `node serve.js 4322` のように番号を変えられます

スマホのブラウザで「ホーム画面に追加」すると、アプリのような全画面表示で確認できます。

## 5. 公開する

来場者に配るには、どこかのURLで見られる必要があります。いちばん安いのはGitHub Pagesです。

1. GitHubにリポジトリを作り、このフォルダの中身をそのまま push
2. Settings → Pages → Source を `main` / `root` にする
3. 数分後 `https://ユーザー名.github.io/リポジトリ名/` で公開される
4. そのURLのQRコードを紙パンフ・立て看板・SNSに載せる

HTTPSで配信されるので、スマホのホーム画面に追加すればアプリのように使えます。

## 6. ファイル構成

```
webパンフ/
├── index.html          読み込み順だけ書いてある入り口
├── serve.js            スマホ確認用の簡易サーバー（node serve.js）
├── css/style.css       見た目（PDFの配色をそのまま再現）
├── js/
│   ├── config.js       ★ここだけ触れば設定が変わる
│   ├── data.js         スプレッドシート取得・デモ値生成・共通ヘルパ
│   ├── quiz.js         診断の質問と、質問を選ぶロジック
│   └── app.js          画面の描画とルーティング
└── data/
    ├── shops.js        ★模擬店・企画マスタ（本番はここを差し替える）
    └── map.js          ★階層別2Dマップ（座標を描き直せば実測図になる）
```

`data/shops.js` と `data/map.js` は中身がJSONそのままです。
`window.SHOPS_DATA = ` の右側だけを編集してください
（`file://` で直接開いても読めるようにJSの形にしてあります）。

## 7. いまダミーになっているもの

10月の企画書までに、実物へ差し替える必要があるものです。

- **模擬店・企画の一覧**（`data/shops.js`）— 全24件はすべて架空。申請データが揃ってから流し込む
- **開催日 6/13・6/14** — コダコマの画面から取った仮の日付
- **キャンパスマップの座標**（`data/map.js`）— 建物の配置は概念図。実測図をなぞって座標を入れ直す
- **待ち時間の計算式** — 「1人あたり40秒」で仮置き（`js/data.js` の `waitMinutes`）
- **売上個数** — 1年生から提供してもらえるかは未確認

## 8. 決めておきたいこと

- トラメガ隊は何分間隔で何店舗を回るのか（＝データの鮮度をどう案内するか）
- 待ち人数が長時間更新されないときの表示（「情報が古い可能性があります」を出すか）
- レビューの荒らし対策（同一端末からの連投は現状ふさいでいない）
- 本サイトとの役割分担（企画書にある「集客低下を避けるための役割分担」）
